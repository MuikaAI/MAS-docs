# 架构概览

Muika-After-Story 将 Core 与聊天平台适配分开。Core 不依赖 NoneBot；`muika_bot` 负责 NoneBot 接入，通过 WebSocket IPC 与 Core 通信。

## 数据流

```text
聊天平台 ↔ Bot 适配器 ↔ WebSocket IPC ↔ Core
                                       ├─ 命令派发 → 命令结果
                                       └─ 事件队列 → Muika 事件循环
                                                    ├─ Brain：对话与主动发言
                                                    ├─ AgentTasks：后台行动与结果事件
                                                    ├─ TopicManager / DigestAgent：话题与阅读
                                                    └─ MemoryManager：经历、日记、事实和状态

对话回复 → Executor → IPC → Bot → 聊天平台
行动结果 → 事件队列 → Brain → 对话回复
```

Core 是单一主人的陪伴核心。适配器过滤输入，IPC 保留连接认证。普通消息进入事件循环，命令直接进入命令派发器。

## 组件职责

| 组件 | 职责 |
| --- | --- |
| `Muika` | 收集事件、推进即时状态、选择对话或话题流程 |
| `MuikaBrain` | 组装人格、持续状态、记忆与当前输入，生成回复 |
| `Agent` / `AgentTasks` | 组装行动提示，保存任务与工具记录，处理继续、纠正、取消和恢复 |
| `MemoryManager` | 保存原始素材、日记、事实版本、持续情绪及工作摘要 |
| `MemoryReasoner` / `ReflectionAgent` | 检索相关记忆，调度每日整理与补做 |
| `TopicManager` / `DigestAgent` | 选择主动话题，从 RSS 形成阅读笔记 |
| `Executor` | 分段发送文本和资源 |
| `CoreWsServer` | 认证适配器连接，转换 IPC 消息 |

## 事件循环

Core 等待队列事件；等待 5 秒仍无输入时产生 `TimeTickEvent`。

| 触发条件 | 处理方式 |
| --- | --- |
| 用户消息 | 保存原文与资源，检索相关记忆，再生成回复 |
| 会话启动 | 区分首次见面与回归，使用已保存的关系和经历 |
| 定时提醒 | 将提醒交给主人格处理 |
| 行动结果 | 核对任务修订号，保存真实结果，再交给主人格回应 |
| 未处理意愿与持续失衡 | 满足空闲条件和主动冷却后进入思考 |
| 孤独、无聊或好奇 | 在对应条件满足时触发对话或话题流程 |
| 普通空闲 | 推进状态，并检查日记与阅读等后台工作 |

非 `time_tick` 事件均记录 INFO。重复时间事件、模型计时和详细执行信息记录 DEBUG。

## 说话与行动属于同一个 Muika

Brain 负责她在对话中的表达，Agent 是她的行动半身。执行较长任务时，用户仍可继续聊天。

1. Brain 的回复可以包含私有 `<memory>`、`<state>` 和 `<agent>` 标签。
2. 记忆笔记保存为待整理素材，状态更新保存她的情绪和意愿。
3. 行动指令交给持久任务；一个任务执行时，其余任务排队等待。
4. 后续纠正、继续与取消进入已有任务，在动作边界生效。
5. 工具结果和执行检查点保存后，结果事件回到 Brain，由她自然地回应用户。

完成行动不等于收到正面反馈。任务回报不会重开她已解决或已放下的意愿；她仍可主动改变决定。
God Mode 的任务交接、Core 自我修改的批准和回滚边界仍使用各自原有流程。

## 会话、日记与重启

原始对话和行动结果逐轮保存。新会话只切换工作上下文，不会重新开始关系，也不即时生成日记。
本地时间 05:00 后的空闲阶段整理前一天，启动和空闲时补做积压日期。`.reflect` 可手动整理今天已有素材。

记忆系统保留日记、事实来源、最早已知互动日期和持续状态。行动任务保存检查点，重启后核对现场并恢复。
定时提醒仍保存在内存中，Core 重启后失效。
